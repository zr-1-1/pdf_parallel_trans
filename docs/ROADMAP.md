# PaperFlow 优化与拓展建议

已完成失败后续译、术语表/文档背景、校订自动保存与导出，以及本地预检和单页试译。复用现有段落、译文和原文副本，无需桌面端或数据库。

## 本次已经完成

模型目录来自官方 Codex App Server，推理强度随模型能力联动，保留本机默认与自定义入口。连接检查和翻译共用设置，任务记录保存选择。DeepSeek 与兼容 API 保持原有调用方式，不混入 Codex 专属参数。

行内公式已接入占位符校验与原文裁片还原；常规双栏按先左后右展开，跨栏标题及图表整体保留；扫描页通过本机 RapidOCR 建立文字层。网页支持自动/手动分栏、自动/关闭/强制 OCR、公式保护开关，并显示解析统计与核对提示。复用现有 Conda 依赖及模型，没有新增安装。

2026-10-24 增加：

- 修复 `run.bat` 换行导致的解析与闪退；校验 Conda/端口，重复启动复用当前项目服务，就绪后打开网页，异常保留日志和窗口。
- 失败、取消、中断后主动续译，复用同任务已完成批次。缓存核对源文件、解析结果、程序和设置；成功读取的 Codex 默认配置固化到任务，密钥不落盘。
- 人工术语表及文档背景，每批携带；冲突术语提交前报错，不重复发送全文。
- 原文/译文搜索、逐段校订、字号调整、独立版本导出和恢复机器译文。公式标记前后端校验，失败后保留旧 PDF 和已提交草稿。
- 显示段落进度、缓存复用数、耗时、失败阶段建议；全部译文已完成时，续译只重新排版，不需要 API Key。

2026-10-26 增加：

- 上传上限默认 200 MB，可通过 `PAPERFLOW_MAX_UPLOAD_MB` 调整，网页同步显示服务端限制；页数上限保持 150 页。
- 校订草稿自动保存、浏览器临时备份、刷新恢复；草稿版本冲突不会覆盖另一窗口的修改，正式导出仍严格检查公式。
- 缓存按格式版本、翻译提示与任务设置判断兼容性，继续校验原文及解析文件哈希；无关代码修改不再使缓存失效。旧缓存验证通过后迁移并保留原清单。
- 本地预检显示原图、段落阅读顺序、OCR/双栏/公式统计，不要求翻译连接；单页试译后可翻译全部选定页，复用已保存译文。试译与全文 PDF 分开保存。
- 原生字体压缩、按需嵌入数学备用字体，减少排版耗时；页眉页脚字体独立命名，修复部分阅读器中的资源冲突。预检界面同步清除上一份 PDF 的预览和下载入口。

## 后续优先级（尚未实现）

| 优先级 | 方向 | 结合当前实现的做法 | 验收目标 |
| --- | --- | --- | --- |
| P1 | 更细的术语与版本管理 | 在现有人工术语和文档背景之上，按章节自动提取上下文、提供指定段落重译及历史版本选择。当前历史文件已保留，网页仅支持恢复机器译文。 | 局部重译不会改动其他人工校订；能明确比较并恢复任意旧版本。 |
| P1 | 复杂版面与公式识别增强 | 在现有双栏、OCR 和公式保护之上扩充真实样本，支持旋转纠正、三栏、浮动侧栏、英文 OCR 空格纠错；评估专用数学 OCR 与人工标记公式区域。 | 统计公式漏检、OCR 错字和阅读顺序错误；复杂扫描公式有可核对的原图与人工修正入口。 |
| P2 | 性能测量与诊断导出 | 已有耗时、失败阶段及建议；后续整理脱敏诊断下载，再依据真实耗时评估 App Server 进程复用和批量大小。 | 诊断不包含密钥、账户信息或整篇论文；性能改动有实际耗时对比。 |
| P2 | 阅读与论文管理 | 校订面板已有段落搜索及原文页码；后续加入 PDF 阅读位置恢复、批注、论文元数据、批量队列与 Zotero 导入导出。 | 每项阅读功能都能定位回原文；导入和导出不会覆盖已有 PDF 或用户批注。 |

## 参考项目如何取舍

- [Reader](https://github.com/cynicalight/reader#readme)：可借鉴按模型能力展示选择、任务恢复与译文复用、原文定位、批注和脱敏诊断。它的完整书库与 Electron 外壳不必一起引入。上述表格是针对本项目的建议，不表示 Reader 的实现可以直接复制。
- [PDFMathTranslate](https://github.com/PDFMathTranslate/PDFMathTranslate#readme)：重点参考公式/版面保护、多翻译后端、翻译缓存和可选 OCR。仓库也链接了 [PDFMathTranslate-next](https://github.com/PDFMathTranslate/PDFMathTranslate-next)；实际接入前需要比较接口、许可证、Conda 依赖与输出格式。
- [Codex 官方 App Server](https://learn.chatgpt.com/docs/app-server) 与 [配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)：模型和强度应以本机返回的能力为准。当前已经使用只读目录查询；是否替换现有 `exec` 翻译通道，应由后续性能测量决定。

本阶段保持本机网页、单用户队列和已有 Conda 环境。当前 OCR 与版面模型已复用本机资源；后续确需安装新依赖或下载其他模型时，再单独评估。
